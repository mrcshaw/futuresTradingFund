Indicator Researcher

The best version uses be_trigger_dollars=200.0, cooldown_bars=10, disarm_only_inside_poc=True, ema_len=20, ema_slope_len=5, is_futures=True, min_delta_pct=5.0, min_slope=0.1. Attempts recorded: 200.

1. The bet
This version tries to catch the behavior named in the script title. It can trade a side the script does not name. The coded conditions that build the entry signal must all be true, including any session filter and cooldown on this version. The fill is on the next bar's open, because the script does not set process_orders_on_close.

2. The stop that is actually active
This version uses a fixed dollar stop. Initial risk is not stated as a point distance, $410. The coded reward is $1,100. The reward-to-risk ratio is 2.69. The win rate required before commission and slippage is about 27.1 percent. If the file codes more than one stop, the figures above are the inputs on the version the engine kept.

3. The target
Take profit on this version: $1,100. Winners are capped at that take profit. This version does not describe a split. The position exits together when the target, the stop, or a session flat is hit.

4. The trailing stop and breakeven
The trailing stop is off in this version, and breakeven is off. The backtest of this version says nothing about a strategy trail. A trail that is not in the code cannot lock profit, cut winners, or replace a profit cap. The account rule is separate. The $2,000 trailing drawdown must not be crossed before the $3,000 profit target is met.

5. Time of day
The coded session is 08:00 to 16:00 Eastern Time. 9:30 is traded with the same rules. The first hour is traded with the same rules. Midday is traded with the same rules. The cash close, 15:00–16:00, is traded with the same rules. The 18:00 reopen is stood aside. The file does not show a forced flat at the session end. Where 9:30 uses the same rules as the rest of the day, that is stated above. The open is the least reliable part of a backtest when orders fill on the bar close and stops are not checked every tick, because one bar can hit both the stop and the target.

6. Costs and size that change the result
Point value is not named in the header or inputs. Contracts are the strategy default. Commission is not in the header. Slippage is not in the header. Pyramiding is not in the header. Cooldown after an exit is whatever cooldown input the file names; if it has none, the script does not wait. Round-trip cost in points was not computed because point value or commission is missing from the file.

7. What the backtest cannot prove
The script does not set fills on the close. Stops are not calculated every tick. No declared input was found unused in the entry. A level that needs future bars is not a live signal.

8. Where this kind of rule set usually makes and loses money
Winners are capped, so a large trend pays only the target. Losers take the full coded stop when a stop is hit. The file does not cut trades with a session flat. The open is inside the session, so the open can whipsaw a bar-close fill. Settled for the best version: profit 982.0, drawdown 1776.2, trades 18, trail cleared: no.
